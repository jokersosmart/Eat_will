# 「阿是要不要好好吃飯」MVP 系統規格

## 產品目的

本系統是一個以**飯局智慧**為核心的專業 Web 應用，協助使用者在商務或社交飯局的局前、局中與局後，依據既有課程知識進行策略規劃、人際觀察與行動復盤。MVP 的重心是讓使用者能在短時間內找到可執行的策略，而非以通用聊天功能取代專業判斷。

## 固定知識架構

| 模組 | 固定結構 | MVP 的呈現與用途 |
| --- | --- | --- |
| 六大部分知識庫 | 目標與框架、人物與角色、場景、時機、話題與五局、實戰與長期養成 | 章節導覽、類別篩選、局前推薦的策略來源 |
| 七大飯局角色 | 資源人、需求人、橋接人、主持人、氣氛人、觀察人、干擾人 | 角色卡、辨識訊號與對應應對策略 |
| 五局十五層 | 破冰、探索、推進、成交、關係；每局三層 | 話題方向、具體做法與注意事項 |
| 局前篩選標籤 | 人數、菜系、時段 | 以情境縮小可閱讀與可執行的知識條目 |

> 角色名稱僅採用指定七種；局別名稱僅採用「破冰、探索、推進、成交、關係」。系統不提供修改、新增或改名的入口。

## 主要使用流程

使用者首先進入「局前規劃」，選擇人數、菜系與時段，並補充本次目標。系統從符合標籤的知識庫條目、相關角色卡與五局建議中組成一份可立即採用的規劃摘要。使用者可接著查看角色識別、選取當前局別和層次取得話題方向，或切換至知識庫深入閱讀。登入後，使用者可將情境、目標及建議儲存為個人飯局紀錄，方便飯後復盤。

| 功能 | 輸入 | 輸出 | 登入要求 |
| --- | --- | --- | --- |
| 局前規劃 | 人數、菜系、時段、目標 | 匹配的策略條目、角色提示、局別建議 | 否；儲存時需要 |
| 角色識別 | 指定角色 | 定義、辨識訊號、應對策略、補充要點 | 否 |
| 五局十五層 | 局別、層次 | 核心層次、話題方向與做法、注意事項 | 否 |
| 知識庫瀏覽 | 六大部分、類別 | 32 筆課程策略條目 | 否 |
| 飯局紀錄 | 局前規劃及 AI 回覆 | 個人紀錄與復盤摘要 | 是，僅 Manus OAuth |
| 智慧建議 | 人物背景、目標、局別、層次 | 受來源條目約束的話題、角色策略、局後復盤摘要 | 否；儲存時需要 |

## LLM 使用規則

LLM 僅在伺服器端呼叫，且每次請求都會帶入與使用者情境相關的知識庫摘錄、角色卡與局別條目。系統提示將明確要求模型**只根據提供的內容回答**；當來源不足以支持結論時，必須回覆「知識庫目前沒有足夠依據」，不得自行編造餐廳、人物判斷、談判條件或其他外部做法。回覆採取固定 JSON 結構，包含「建議、依據條目、注意事項、局後復盤問題」，以保留來源可追溯性。

## MVP 資料模型摘要

| 資料表 | 目的 | 主要欄位 |
| --- | --- | --- |
| `knowledge_entries` | 儲存六大部分 32 筆策略內容 | section、category、title、content、peopleTags、cuisineTags、timeTags、sortOrder |
| `dinner_roles` | 儲存指定七大角色卡 | name、definition、signals、strategy、notes、sortOrder |
| `conversation_stages` | 儲存五局十五層 | stage、layer、coreFocus、topicGuidance、cautions、sortOrder |
| `dinner_records` | 儲存登入使用者的飯局規劃與復盤 | userId、title、guestCount、cuisine、timeSlot、objective、stage、layer、context、aiAdvice、reflection、createdAt |
| `user_preferences` | 儲存登入使用者的預設偏好 | userId、defaultGuestCount、defaultCuisine、defaultTimeSlot、updatedAt |

## 視覺與互動規格

介面採用暖米白背景、深海軍藍作為主要文字與結構色、金色作為提示與層級色。背景由低對比的 CSS 黃金比例螺旋與交錯圓形構成，避免產生影響閱讀的裝飾性圖片依賴。版面以公共產品的頂部導覽為主，行動裝置上以可捲動的分段導覽呈現。所有表單都有清晰標籤、鍵盤焦點與載入／錯誤狀態。

## 驗收條件

| 編號 | 可驗收結果 |
| --- | --- |
| AC-01 | 使用者可用人數、菜系、時段取得資料庫篩選後的局前策略。 |
| AC-02 | 介面完整呈現且僅呈現七個指定角色名稱。 |
| AC-03 | 介面完整呈現且僅呈現五個指定局別與每局三層內容。 |
| AC-04 | 知識庫可按六大部分與類別篩選，並忠實顯示來源內容。 |
| AC-05 | 只有 Manus OAuth 登入方式；登入後可以新增、查看及儲存自己的飯局紀錄。 |
| AC-06 | AI 回覆附有知識庫依據，且在來源不足時拒絕臆測。 |
| AC-07 | 桌面與手機畫面均維持可讀性與一致的神聖幾何視覺語言。 |
